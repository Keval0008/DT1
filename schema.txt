## 1. `dim_business_line`

Makes the business-line set **data**, so entities with different lines need no code change.

```sql
CREATE TABLE dim_business_line (
    entity_code    TEXT    NOT NULL,
    business_line  TEXT    NOT NULL,
    ordinal        INTEGER NOT NULL,
    role           TEXT    NOT NULL CHECK (role IN
                     ('rollup_total','operating','centre','inactive')),
    in_cgu_rollup  INTEGER NOT NULL CHECK (in_cgu_rollup IN (0,1)),
    in_cgu_fcfe    INTEGER NOT NULL CHECK (in_cgu_fcfe   IN (0,1)),
    is_active      INTEGER NOT NULL CHECK (is_active     IN (0,1)),
    PRIMARY KEY (entity_code, business_line)
);
```

| Column | Meaning |
|---|---|
| `ordinal` | Display order; sort on this, never alphabetically |
| `role` | `rollup_total` = the Total identity; `centre` = corporate centre |
| `in_cgu_rollup` | Contributes to the Total identity — from `cgu_rollup` |
| `in_cgu_fcfe` | Included in CGU free cash flow — inverse of `exclude_cgu_fcfe` |
| `is_active` | 0 = present in the template but carrying only zeros |

**Example (Singapore).** Derived from `cgu_rollup = "Total=CIB+iWPB+HK Retail+HK Commercial+CC"`
and `exclude_cgu_fcfe = "CC"`:

| entity_code | business_line | ordinal | role | in_cgu_rollup | in_cgu_fcfe | is_active |
|---|---|---|---|---|---|---|
| 4200 | Total | 0 | rollup_total | 0 | 0 | 1 |
| 4200 | CIB | 1 | operating | 1 | 1 | 1 |
| 4200 | iWPB | 2 | operating | 1 | 1 | 1 |
| 4200 | HK Retail | 3 | operating | 1 | 1 | **0** |
| 4200 | HK Commercial | 4 | operating | 1 | 1 | **0** |
| 4200 | CC | 5 | centre | 1 | **0** | 1 |

HK Retail and HK Commercial carry zeros throughout the template. `is_active = 0` records
that they are *present and nil* rather than *absent* — a distinction that matters when
diffing quarters.

## 2. `dim_period`

Makes the horizon **data**, so 5-, 6- or 7-year entities need no code change.

```sql
CREATE TABLE dim_period (
    entity_code  TEXT    NOT NULL,
    period       TEXT    NOT NULL,
    ordinal      INTEGER NOT NULL,
    period_type  TEXT    NOT NULL CHECK (period_type IN
                   ('opening','forecast','terminal','historical')),
    PRIMARY KEY (entity_code, period)
);
```

`period` is `TEXT` because `Opening` and `Terminal` are first-class periods alongside
calendar years. **Always order by `ordinal`, never by `period`.**

**Example (Singapore, `look_ahead = 6`, `testing_date = 2026-02-28`):**

| entity_code | period | ordinal | period_type |
|---|---|---|---|
| 4200 | Opening | 0 | opening |
| 4200 | 2026 | 1 | forecast |
| 4200 | 2027 | 2 | forecast |
| 4200 | 2028 | 3 | forecast |
| 4200 | 2029 | 4 | forecast |
| 4200 | 2030 | 5 | forecast |
| 4200 | 2031 | 6 | forecast |
| 4200 | Terminal | 7 | terminal |

An entity with `look_ahead = 7` gets one additional forecast row. Nothing else changes —
no DDL, no query, no engine branch.

## 3. `dim_item`

Declares units, grain and horizon policy. **Stored inside every run**, so a run remains
self-describing years later.

```sql
CREATE TABLE dim_item (
    item             TEXT PRIMARY KEY,
    category         TEXT    NOT NULL,
    canonical_unit   TEXT    NOT NULL,
    grain            TEXT    NOT NULL CHECK (grain IN
                       ('line_period','line_only','entity_period')),
    sign_convention  TEXT,
    horizon_policy   TEXT    NOT NULL CHECK (horizon_policy IN
                       ('exact','extend_last','zero_fill','not_applicable')),
    required         INTEGER NOT NULL CHECK (required IN (0,1)),
    description      TEXT
);
```

**Example (seed values implied by the template):**

| item | category | canonical_unit | grain | sign_convention | horizon_policy | required |
|---|---|---|---|---|---|---|
| `pbt` | pnl | mn_lcy | line_period | | exact | 1 |
| `rwa` | balance_sheet | mn_lcy | line_period | | **extend_last** | 1 |
| `cet1_required` | capital | ratio | line_period | | extend_last | 1 |
| `cet1_actual` | capital | ratio | line_only | | not_applicable | 1 |

  once, at ingestion.

## 4. `fact_input`

The main table. 412 rows for Singapore.

```sql
CREATE TABLE fact_input (
    entity_code    TEXT NOT NULL,
    business_line  TEXT NOT NULL,   -- 'ENTITY' for entity-level items
    item           TEXT NOT NULL,
    period         TEXT NOT NULL,   -- 'NA' for time-invariant items
    layer          TEXT NOT NULL CHECK (layer IN
                     ('base','actuals','overlays','manual_adj')),
    value          REAL,            -- canonical units
    unit           TEXT NOT NULL,
    value_source   REAL,            -- as supplied
    unit_source    TEXT,
    source_ref     TEXT,            -- traceable back to a template cell
    PRIMARY KEY (entity_code, business_line, item, period, layer),
    FOREIGN KEY (entity_code, business_line)
        REFERENCES dim_business_line(entity_code, business_line),
    FOREIGN KEY (item) REFERENCES dim_item(item)
);

CREATE INDEX ix_fact_item   ON fact_input(entity_code, item, period);
CREATE INDEX ix_fact_line   ON fact_input(entity_code, business_line, item);
CREATE INDEX ix_fact_period ON fact_input(entity_code, period);
```

Sentinels are used rather than NULLs because **SQLite treats NULL as distinct from NULL
in primary keys**, which silently disables uniqueness enforcement.

### 4.5 Example — tax_rate (flat rate plus optional override)

| business_line | item | period | layer | value | unit | note |
|---|---|---|---|---|---|---|
| Total | tax_rate | NA | base | -0.1375 | ratio | flat rate |
| CIB | tax_rate | NA | base | -0.1375 | ratio | flat rate |
| iWPB | tax_rate | NA | base | -0.1375 | ratio | flat rate |
| CIB | tax_rate | 2028 | base | -0.1700 | ratio | *illustrative override* |

Resolution: `COALESCE(period_specific, flat)`. The per-year columns are empty in the
Singapore template, so only `NA` rows exist today — but the schema supports overrides
with no change. A wide design would need a second table.

The `adj_type` column maps onto `item`, so adjustments live in the same table as the
values they adjust, distinguished only by `layer`. Effective value is then:

```sql
SELECT business_line, period,
       SUM(CASE WHEN layer IN ('actuals','overlays','manual_adj')
                THEN value ELSE 0 END) AS effective_pbt
FROM fact_input
WHERE entity_code = '4200' AND item = 'pbt'
GROUP BY business_line, period;
```
